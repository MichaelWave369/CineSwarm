# Stage 36 — Field Bridge Charter

## Selection and authority

The controlling prompt selects one bounded relationship for field preparation: a local CineSwarm coordinator connected to user-owned Windows PCs running CineSwarm nodes. This is authority to prepare a reversible protocol and runnable package, not evidence that physical deployment, model acquisition, firewall change, or inference occurred.

## Outcome

Allow Mikey to prove local orchestration first, then qualify each machine honestly for native video work. Preserve local custody, explicit receipts, human media review, separate release authority, and easy exit.

## Field boundary

- Version: `0.1.0` private candidate.
- Environment: loopback first; trusted private LAN only after the operator deliberately sets a secret and firewall rule.
- People: no participant, operator, steward, or reviewer is inferred beyond the user as decision owner.
- Data: synthetic orchestration fixture before any private creative asset.
- Models: no automatic acquisition. A ModelManifest must bind exact source, revision, hash, license finding, runtime, hardware class, and approved use.
- Spend: no paid service, hardware purchase, or provider call is authorized.
- Release: field ACCEPT is never public-release authorization.

## Readiness truth

The software protocol is prepared and locally tested in the build environment. Physical Windows, LAN, GPU/CUDA, model/license, two-PC behavior, and Pocket Spark rendering remain **Unable to Verify** until the field protocol produces receipts. The official Wan 2.2 TI2V 5B published single-GPU path requires at least 24 GB VRAM; the source-asserted RTX 5070 12 GB cannot satisfy that profile.

## Entry gates

1. Preserve a backup and source package hash.
2. Install the local wheel and pass `cine doctor` on loopback.
3. Complete the deterministic test-backend job.
4. If using LAN, establish private-subnet binding, a random shared secret, and the narrow firewall rule.
5. Register the second node and exercise restart/recovery.
6. Only then decide whether to use a qualifying 24 GB+ Wan node or initiate a new Stage 3 backend specification.

## Stop conditions

Stop on unexpected network exposure, secret disclosure, hash mismatch, database corruption, low storage, unverified model terms, external-provider call, hardware shortfall, repeated lease failure, or operator discomfort. Preserve evidence, stop node/coordinator processes, close the firewall rule, and restore only into an empty target.

## Success and exit

Planning success means the runbooks/scripts are complete and verified where possible. Field success requires signed receipts from the actual machines. Exit remains available at every gate; local data and backups remain under the user’s custody.
